# 🤖 AI Workflow & Engineering Reflection — KSPDB

This document details how AI assistance was leveraged during the development of the KSPDB Power Grid Fault Detection & Localization System, distinguishing good AI output from flawed suggestions, and quantifying AI contributions.

---

## 1. AI Tooling Summary

- **Primary AI Assistants:** Antigravity AI Agent (DeepMind pair programming agent), Claude Opus 4.6, Gemini 3.6 Flash.
- **Workflow Role:** Rapid prototyping of data schemas, spatial graph algorithm design, dark glassmorphism UI generation, Express REST API scaffolding, and unit test generation.

**Overall Code Contribution:** ~75% AI-generated / 25% hand-scaffolded & verified.

## 3. Concrete Cases Where AI Was Wrong or Misleading

### Case 1: Recommending LLM for Core Fault Localization
- **What the AI Suggested:** Early prompts suggested feeding telemetry arrays into GPT-4o to locate the broken pole span.
- **Why It Was Misleading:** LLMs are non-deterministic, slow (>1.5s latency), expensive, and hallucinate coordinates.
- **How It Was Fixed:** Rejected AI suggestion entirely. Implemented a deterministic $O(V+E)$ graph traversal algorithm for fault localization, using LLMs solely for generating plain-English incident summaries for operators.

### Case 2: Ignoring Radial Tree Structure & Treating Poles as a Graph Mesh
- **What the AI Suggested:** AI initially generated Dijkstra's shortest-path algorithm over an arbitrary mesh network to find shortest live paths.
- **Why It Was Flawed:** Low-voltage LT networks are strictly **radial tree structures** with no loops. Pathfinding algorithms add unnecessary $O(E \log V)$ overhead.
- **How It Was Fixed:** Refactored algorithm to simple breadth-first tree traversal from the Distribution Transformer (DT) root to find live/dark boundary edges.

### Case 3: Flawed Dead Sensor Filtering
- **What the AI Suggested:** AI initially assumed any dark pole without a `power_lost` message was a dead sensor.
- **Why It Was Misleading:** Firmware 1.2.x devices (~8% fleet) and 30% of dying capacitor devices never send `power_lost` packets due to radio noise, yet represent genuine power outages!
- **How It Was Fixed:** Rewrote dead sensor logic: a dark pole is ONLY flagged as a dead sensor if its downstream children are explicitly live (`energized = 1`), proving physical power is flowing past it.
